# ほかのゲーム・ほかのアプリ（相互リンク）の配信設定

**正本は `promo/apps.json`（version 2。ゲームと実用系アプリの両方）。** 新しい版のアプリはこれを読む。
`promo/games.json`（version 1・ゲームだけ）は、**公開済みの旧版アプリ向けに残している生成物**。直接編集せず、`python3 scripts/build_promo_games.py` で `apps.json` から作り直す（`check_site.py` が、ずれていないか確認する）。

## apps.json の項目（v2）

| 項目 | 内容 |
|---|---|
| `inlineLimit` | 設定画面に直接並べる最大数（既定 3）。超えた分は「もっと見る」の子ページ（全アプリを出す） |
| `apps[].category` | `game` か `utility`。アプリは**自分と同じ種類だけ**を出す（ゲーム → ゲーム、実用系 → 実用系）。見出しは「ほかのゲーム」「同社のほかのアプリ」 |
| `apps[].priority` | 小さいほど先に出す（種類の中での順番） |
| そのほか | 下の「項目」と同じ（`games[]` の代わりに `apps[]`） |

以下の説明は、`games.json` と `apps.json` で共通（`games[]` は `apps[]` と読み替える）。

---
# 項目（共通）

各ゲームアプリの「ほかのゲーム」画面は、起動中に `https://ryo-lab.dev/promo/games.json` を 1 回取得して表示する。
このファイルを直して main にマージするだけで、アプリのビルド・アップデートなしで表示を切り替えられる（GitHub Pages の反映は 1〜2 分、アプリ側のキャッシュは最大 10 分前後）。

## 項目

| 項目 | 内容 |
|---|---|
| `games[].id` | アプリの固定 ID。アプリ側は自分の ID の行を一覧から除く |
| `name` / `tagline` | 表示名と 1 行の紹介文 |
| `icon` | アイコン画像の URL（任意） |
| `android` / `ios` | OS ごとの状態。`status` と `url` を持つ |

### `status`

- `hidden`: そのアプリを、その OS の利用者には出さない（未配信・審査中のとき）。
- `released`: ストアへのボタンを出す。`url` が必須。

アプリは、**いま動いている OS の状態だけ**を見る（Android の端末では `android`、iPhone では `ios`）。

## 新しいアプリ・審査通過のとき

1. 該当アプリの該当 OS の `status` を `released` にし、`url`（ストアのページ）を入れる。
2. PR を作ってマージする（`python3 scripts/check_site.py` が通ることを確認）。
3. 反映を確認する（Pages のデプロイ後、各アプリを再起動すると反映される）。

## 設定画面での並べ方（`inlineLimit`）

表示するゲーム（自分を除く）が `inlineLimit` 本以下なら設定画面に直接並べ、**超えたら**「ほかのゲーム」の子ページ（1 行の入口）に切り替わる。既定は 5。変えるときは games.json の `inlineLimit` を直す（アプリの更新は不要。この項目を知らない古いアプリは 5 のまま）。

読み込みに失敗したとき（オフラインなど）や形式が不正なときは、画面ごと出さない。形式を変えるときは `version` を上げ、古いアプリでも壊れないようにする（新しい項目は任意にする）。
